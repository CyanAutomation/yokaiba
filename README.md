# Yokaiba

[![Validate](https://github.com/CyanAutomation/yokaiba/actions/workflows/validate.yml/badge.svg?branch=main)](https://github.com/CyanAutomation/yokaiba/actions/workflows/validate.yml) [![Deploy Cloudflare Worker](https://github.com/CyanAutomation/yokaiba/actions/workflows/deploy-cloudflare.yml/badge.svg?branch=main)](https://github.com/CyanAutomation/yokaiba/actions/workflows/deploy-cloudflare.yml)

Yokaiba generates deterministic, uniquely solvable judo logic-grid puzzles for games and integrations. Its hosted service provides a public REST API and an authenticated Model Context Protocol (MCP) endpoint.

Yokaiba is intended for game and integration developers. Its hosted REST API and MCP service are the supported integration surfaces; this private application package does not publish a stable TypeScript SDK.

## Capabilities

- Deterministic puzzle generation from a versioned template and seed.
- Uniquely solvable tournament scenarios with clues, generated by an internal TypeScript constraint solver.
- REST endpoints for scenarios, generation, answer verification, hints, and optional anonymous outcome events.
- Streamable HTTP MCP tools for scenario discovery and puzzle generation, with token-protected puzzle actions when configured.
- A deterministic 1–12 puzzle difficulty model, with separate optional language review and observed player outcomes.

## Try the hosted API

The [API documentation](https://yokaiba.scheimann.workers.dev/docs) and [OpenAPI contract](https://yokaiba.scheimann.workers.dev/openapi/v1.yaml) list the REST interface.

Generate a reproducible puzzle with a template ID and seed:

```sh
curl -fsS 'https://yokaiba.scheimann.workers.dev/v1/puzzles/generate?templateId=tournament-order-v2&seed=first-puzzle'
```

Current response preview for this seed:

```text
templateId: tournament-order-v2
seed: first-puzzle
difficulty: level 2 (Easy)
clues: 7
solution: not returned
```

The response includes the puzzle specification and clues, plus replay metadata. The hidden solution is not returned. Answer verification and hints require a configured `PUZZLE_TOKEN_SECRET`; see [operations and deployment](docs/operations-and-deployment.md#browser-cors-and-abuse-controls) for setup and token limitations.

## Run locally

Requirements: Node.js 24.x and npm. The repository pins the Node.js major version in `.nvmrc`. From the repository root:

```sh
npm ci
npm run dev
```

Wrangler serves the local Worker at `http://localhost:8787` by default. In another terminal, generate a puzzle:

```sh
curl -fsS 'http://localhost:8787/v1/puzzles/generate?templateId=tournament-order-v2&seed=first-puzzle'
```

This first result does not require secrets. Local answer verification and hints need a `PUZZLE_TOKEN_SECRET` in Wrangler's local development secrets; production credentials must not be copied into local files. See the [development guide](docs/development.md) and [operations guide](docs/operations-and-deployment.md) for optional configuration and troubleshooting.

## Integrate with Yokaiba

- **REST:** Start with the [API usage guide](docs/api-usage.md), [API documentation](https://yokaiba.scheimann.workers.dev/docs), or [full OpenAPI contract](https://yokaiba.scheimann.workers.dev/openapi/v1.yaml). The [ChatGPT Actions OpenAPI contract](https://yokaiba.scheimann.workers.dev/openapi/chatgpt-actions-v1.yaml) is a compact alternative.
- **MCP:** Connect to `https://yokaiba.scheimann.workers.dev/mcp`. The endpoint uses Streamable HTTP and requires a configured API key and hostname allowlist. Setup and client configuration are in the [operations and deployment guide](docs/operations-and-deployment.md#mcp-and-deployment).
- **Difficulty:** Read how logical, semantic, and observed difficulty are measured in [difficulty and calibration](docs/difficulty-and-calibration.md).

## Develop and contribute

The repository uses Node.js 24.x, pinned by `.nvmrc` and declared in `package.json`. Validate a change locally with:

```sh
npm run docs:check
npm run typecheck
npm test
npm run build
```

For a component map and request flow, see the [Architecture overview](docs/development.md#architecture). For larger changes, open a [GitHub issue](https://github.com/CyanAutomation/yokaiba/issues) to discuss the approach before submitting a pull request. Pull requests should include relevant tests and documentation updates. The [development guide](docs/development.md) describes the local workflow and contribution expectations.

## Deploy

`npm run deploy` runs `wrangler deploy` and publishes to the Cloudflare account configured for the checkout. It is a remote deployment command, not part of local verification. The GitHub Actions deployment workflow runs on `main` and targets the `production` environment. See the [operations and deployment guide](docs/operations-and-deployment.md#github-workflow-policy) before changing deployment configuration.
